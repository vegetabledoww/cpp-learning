# C++ 题目整理

将 `D:\Code\C++code` 维护成适合初学者阅读、可以直接运行的学习仓库。

## 首要原则：学习题优先

- 本仓库中的题目默认用于 C++ 和算法练习，不按生产工程设计。第一目标是正确满足题意、通俗易懂、方便新手手敲和复盘。
- 简单扫描、基础容器或直接模拟能够满足题目约束时，优先采用这种实现；不要只为追求更低的理论复杂度，引入多张持久状态表、多层抽象或需要复杂同步的工程结构。
- 只有题目明确给出会影响通过结果的数据规模、性能要求，或者简单方案无法正确完成题意时，才增加必要的优化，并说明引入它的具体原因和理解成本。
- 用户已有直观且可行的思路时，先沿着该思路完成主学习版本。工程化或高性能实现可以作为可选对照，但不能默认替换更适合学习的版本。

## 必须执行的流程

1. 决定目录或修改文件前，重新读取当前源码、目标目录、`README.md` 和 `MIGRATION_MAP.md`。磁盘上的最新内容优先于对话中的旧信息。
2. 按题目最主要的学习目标分类，不要按所有辅助技术分类。优先使用已有目录；确实没有合适分类时，才新建名称明确的目录。分类存在歧义时，简要说明选择依据。
3. 创建或补全题目之前，读取 [题目文件格式](references/exercise-format.md)，遵循其中的源码结构和测试要求。
4. 尽量保留用户的代码骨架、变量、注释和原始思路。只做让代码正确、清楚、便于学习所必需的最小修改；除非用户明确要求，否则不要主动优化或大范围重构。
5. 使用仓库当前工具链，以 C++17 和 `-Wall -Wextra -pedantic` 编译，然后运行题面样例和针对性的边界测试。逻辑风险较高时，增加反例或与简单参考实现对照。结束后只清理本轮创建的临时产物。
6. 新增分类或重要学习主题时更新 `README.md`；移动或重命名源码时更新 `MIGRATION_MAP.md`；全新文件不需要添加迁移记录。
7. 最终说明文件路径、分类依据、重要改动和实际验证结果。完善过程中修复了正确性问题时，必须明确指出。

## 仓库边界

- 未得到单独、明确的确认时，绝不移动、重命名、修改、清理 `29project`，也不把它列为整理候选。
- 保留用户同时进行的修改。如果移动后旧路径重新出现，先比较新旧版本，把用户最新内容带到目标位置，再处理重复文件。
- 将 `.exe` 视为构建产物。除非用户明确要求，否则不移动或删除已有可执行文件。验证程序放入 `build` 或临时目录，并清理本流程创建的验证产物。
- 不进行无关的格式化、元数据修改或目录调整。

## 学习风格

- 题面和注释使用中文。重点解释决策、维护状态、公式和边界条件，不要逐行复述显而易见的赋值。
- 优先使用基础标准 C++ 和明确的辅助函数。除非它本身是学习主题或确实能明显简化算法，否则避免 lambda、函数对象和不必要的高级 STL 写法。
- 保留在线判题平台要求的函数签名，例如 `class Solution`，同时让本地 `.cpp` 可以独立编译运行。
- 用户要求创建手敲文件（例如 `do.cpp`）时，只放入题目、必要头文件、函数签名和可运行测试；除非用户要求答案，否则核心实现保持未完成。
