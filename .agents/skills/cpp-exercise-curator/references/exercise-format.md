# C++ 题目文件格式

在 `D:\Code\C++code` 中新增或补全练习题时使用以下格式。

## 源码结构

1. 文件最前面放置块注释，内容包括：
   - 题目的正式名称，以及已知的平台和题号；
   - 完整、独立的中文题面，说明输入含义和需要返回的结果；
   - 至少两个样例，每个样例都包含输入、输出和简短的结果推导；
   - 只有当约束会影响类型选择、复杂度或边界处理时，才补充约束。
2. 只包含源码实际使用的标准头文件，优先使用具体头文件，不使用 `bits/stdc++.h`。
3. 保留平台要求的类和函数签名。小型辅助函数放在题解附近，并使用含义明确的名称。
4. 在核心算法附近添加简短中文注释，说明维护的状态、循环或递归的出口以及公式成立的原因。
5. 添加本地 `main()`，运行题面中的样例和至少一个有意义的边界用例，同时打印期望值和实际值。表格化运行多个用例时，使用失败计数或退出码判断结果；不要只依赖 `assert`，因为定义 `NDEBUG` 后它不会执行。
6. 文件末尾添加简短的“收获点”注释，总结可复用的算法模板及时间、空间复杂度。

## 测试要求

- 如果题解会排序或修改参数，每个样例都使用各自独立的可变输入。
- 如果答案顺序不限，只在测试或打印代码中规范化结果后再比较。
- 根据题目选择最容易出错的边界：允许时测试空输入或单元素，还可以测试恰好达到窗口长度、重复值、并列规则、不连通区域或整数溢出。
- 中间计算可能超过 `int` 时使用 `long long`，并在发生类型提升的表达式旁解释原因。
- 同时确认编译成功和实际输出正确。比较器、并列规则、有状态设计题和图搜索不能只做语法检查。

## 分类原则

- 读取当前目录树和 `README.md`，不要依赖写死的分类清单。
- 按完成决定性操作的技术分类。例如，频次统计可能只是预处理，而限制容量的 `priority_queue` 才负责真正的 Top-K 筛选。
- 多技术联合题放到与本次学习目标最接近的分类中，并在题目注释或 README 说明辅助技术。
- 移动源码时保留最新内容，并更新全部旧路径到新路径的记录。除非用户明确要求，否则不处理已有构建产物。
