# array 与 vector：相同的数组接口，不同的长度管理

[运行对照示例](array_vector_comparison.cpp)可以直接看到每种操作的期望值和实际值。

`array<int, 3>` 是“固定装三个 int 的对象”；`vector<int>` 是“管理一串数量可以变化的 int 的对象”。如果你确定一条记录永远有三个坐标，`array` 很合适；如果元素数量取决于输入或需要不断追加，使用 `vector`。

## 相同点与不同点

| 比较项 | `array<int, 3>` | `vector<int>` |
| --- | --- | --- |
| 长度 | 编译期固定为 3，是类型的一部分 | 运行期决定，不是类型的一部分 |
| 不同长度是否同类型 | `array<int,3>` 与 `array<int,4>` 类型不同 | 长度 3 和长度 4 都是 `vector<int>` |
| 存储 | 元素连续，放在 array 对象内部 | 普通元素连续，存放在 vector 管理的动态存储中 |
| 元素访问 | `[]`、`at()`、`front()`、`back()`、`data()` | 同左 |
| 遍历与排序 | 范围 for、迭代器、`std::sort` | 同左 |
| 大小与容量 | `size()` 恒为 3，没有 `capacity()` | `size()` 是元素数，`capacity()` 是已分配空间可容纳的元素数 |
| 增删元素 | 没有 `push_back`、`pop_back`、`insert`、`erase` | 支持增删元素 |
| 改变大小 | 没有 `resize`、`reserve`、`clear` | `resize` 改大小，`reserve` 预留容量，`clear` 清空元素 |
| 整体拷贝和赋值 | 支持，相同类型间逐元素复制 | 支持，目标得到独立的元素存储 |
| 作为函数参数 | 不会自动退化成指针，参数通常带固定长度 | 参数不用指定长度 |
| 交换 | `swap` 交换对应元素，O(N) | 默认分配器下 `swap` 通常交换存储管理信息，O(1) |
| 典型用途 | 坐标、RGB、固定字段记录、固定大小计数表 | 动态输入、结果集合、大小运行时确定的数组 |

这里的连续普通元素存储讨论不包含特殊的 `vector<bool>`。拷贝若保存的是原始指针，复制的是指针值，并不会自动复制指针指向的对象。

## 初始化最容易写混

```cpp
array<int, 3> a{};           // {0, 0, 0}
array<int, 3> b = {7};       // {7, 0, 0}
array<int, 3> c = {1, 2, 3};
c.fill(9);                  // {9, 9, 9}

vector<int> x;              // 空数组
vector<int> y(3);           // {0, 0, 0}
vector<int> z(3, 7);        // {7, 7, 7}
vector<int> w{3, 7};        // {3, 7}，只有两个元素
```

局部变量写成 `array<int, 3> a;` 时，三个 int 未初始化，不能直接读取。初学时推荐 `a{}`，然后按需赋值。

`array<int, 0>` 合法，`empty()` 为 true，但没有可访问的元素。非零长度的 `array` 无法“清空成零个元素”：`fill(0)` 只把值改为 0，长度没有变化。

## reserve 和 resize

```cpp
vector<int> values;
values.reserve(10);  // size 仍为 0，只是预留了空间
// values[0] = 5;    // 错误：还不存在第 0 个元素
values.push_back(5); // size 变成 1
values.resize(3);   // {5, 0, 0}，创建两个新元素
```

`array` 根本不需要这两个接口：它创建时就已经有 N 个元素，也不会扩容。`vector::clear()` 则销毁全部元素，使 size 变成 0，容量通常可继续复用；不要把它理解为“必然归还所有存储”。

## 拷贝、引用和函数参数

```cpp
int SumCoordinate(const array<int, 3>& point); // 只读，不复制三个元素
void ChangeCoordinate(array<int, 3>& point);  // 能修改调用者的对象
int SumValues(const vector<int>& values);    // 可以接受任意长度
```

`array<int,3>` 不能直接传给要求 `array<int,4>` 的函数。固定容量非常多样时可用函数模板接收 N，但当前先掌握固定长度接口即可。

两者按值传参都会复制元素，按引用传参才是访问原对象。`const` 引用表达“不复制，并且不通过这个参数修改元素”。普通 C 数组的函数参数常退化为指针；`array` 没有这个规则。需要裸元素指针时，用 `.data()`。

## 元素地址和迭代器

`array` 没有扩容，所以修改值、排序、`fill` 不会改变各个元素槽位的地址。对象仍然有生命周期：对象销毁后，指向其元素的指针当然不能继续使用。

`vector` 有几种不同情况：

- 扩容重新分配存储后，原元素的指针、引用和迭代器全部失效。
- 末尾追加而没有扩容，原有元素的引用和迭代器仍有效，但旧的 `end()` 失效。
- 中间插入即使没有扩容，也会使插入位置及之后的迭代器、指针和引用失效。
- `erase` 会使删除位置及之后的迭代器、指针和引用失效；安全遍历删除要接住返回的下一个迭代器。

提前 `reserve` 可以减少扩容次数，但不能让所有修改操作都保持迭代器有效。

## 不能简单用“栈与堆”区分

准确说法是：`array` 的元素在自身对象内部；`vector` 的元素存储由容器通过分配器另外管理。

`array` 对象可以是局部变量、静态变量、类成员，也可以被动态分配；如果包含它的对象在动态存储中，它的元素也跟着在那里。`vector` 对象本身同样可以放在这些位置。两者的区别是存储组织和长度管理方式，不是变量只能放在哪一块内存。

## 如何选择

- 三维坐标：`array<int,3>`，三个字段的数量明确，整体复制和排序也方便。
- 运行时输入 n 个数：`vector<int> values(n)`，即使以后不追加，也应使用能接受运行时长度的容器。
- 不知道会产生多少个答案：先建空 `vector`，然后 `push_back`。
- 26 个字母的计数：`array<int,26> count{}`，长度固定，自动补零。

不要仅凭“array 一定更快”选择它：两者的元素访问都是 O(1)、遍历都是 O(n)，实际性能取决于数据规模、分配次数和访问方式。
