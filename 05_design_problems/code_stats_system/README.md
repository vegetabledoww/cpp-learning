# 代码量统计系统

[solution.cpp](solution.cpp) 根据提供的代码补成完整学习题，包含题面、两个操作序列样例和可运行测试。原题平台与完整约束未知，源码开头的“本练习约束”是整理时明确的约定，不能作为已核实的原题限制。

本题放在设计题目录，因为学习重点是维护系统状态、执行修改和统计接口；哈希表与排序是实现这些接口的工具。

## 保留原来的实现思路

- `repo` 保存全部仓库，`mp[0]` 用于全局统计，其余键表示具体产品。
- `repo_code_lines` 每一行仍然是 `{仓库编号, 语言编号, 代码量}`。
- `exist` 仍采用“没找到返回 0，找到返回下标加 1”的约定。
- `ChangeCodelines` 查找记录后累加；没有记录就新增。
- `StatLanguage` 先按仓库汇总，再筛掉零代码量，最后按“总行数降序、编号升序”排序。

这是单系统的普通函数版本，沿用提供代码的接口形式。重新调用 `CodeStatsSystem` 会清空上一轮状态；它目前不是可以同时创建多个对象的类版本。

## 做了哪些局部整理

1. 初始化清空三个全局容器，避免再次初始化时混入旧仓库和旧代码量。
2. 使用 `mp.find(productId)`，直接得到产品的仓库列表；通过 const 引用读取，避免复制列表。
3. 空记录表直接由 `exist` 返回 0，不再重复一个空表分支。
4. 普通函数 `CompareLanguage` 替代 lambda，明确“先比较总量，再比较编号”。
5. 汇总值和排序键使用 `long long`。单仓库返回值保留 `int`，因此本练习要求每个仓库每种语言的当前值能用 int 表示。
6. 将原先未打印的查询结果改为期望值与实际值对照，失败时返回非零退出码。

## 必须先看清的约定

语言编号按 `1～6` 处理，所以数组大小为 7，下标 0 不使用。实际产品编号不能为 0，因为它表示全局查询。每个仓库在初始化列表中只出现一次，因此全局汇总不会重复计算同一仓库。

更新只针对已登记仓库，并保证更新后的代码量非负。不增加非法输入的处理分支，也不把这些未确认的情况误当作原题要求。如果后续拿到原题，应先核对语言编号、仓库归属、代码量范围以及接口签名。

## 例子中的排序

产品 10 的两个仓库中，语言 2 的代码量分别为 100 和 50，语言 1 为 150。因此先得到 `{语言1:150, 语言2:150}`，相同总量按编号排序，返回 `{1,2}`。

产品 20 的语言 3 为 200。全局汇总后是 `{语言1:150, 语言2:150, 语言3:200}`，先比较行数，所以结果是 `{3,1,2}`，而不是单纯按编号排列。

这也说明为什么应该先完成汇总，再进行一次排序，不能仅按每条仓库记录分别排序。

## 验证与复杂度

内置测试覆盖原始调用序列、多产品隔离、同语言跨仓库相加、同量排序、排名变化、减到零、空产品、不存在的产品、语言编号边界、重复初始化，以及全局汇总超过 int 的情况。

修改时扫描 M 条记录，为 O(M)；查询包含 R 个仓库的产品时为 O(RM + L log L)，这里 L=6。若后续明确存在大数据性能要求，可以再改成按仓库编号直接查各语言数组；当前保留直观版本，不额外维护多份总量。

.\build\code_stats_system.exe
