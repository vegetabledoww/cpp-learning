# DHCP 地址分配系统

[solution.cpp](solution.cpp) 保留了原草稿的 `DHCPServerSys`、`Request`、`Release` 和两个 `vector<pair<string,string>>` 表，补成有题面、样例和测试的完整学习题。

原题未提供完整规则。地址池 `192.168.0.1～192.168.0.4`、分配优先级、失败返回空字符串，均为本练习约定。以后拿到原题，需先核对这些规则。这里仅模拟地址分配，不执行实际 DHCP 网络通信。

## 分配优先级

| 顺序 | 情况 | 操作 |
| --- | --- | --- |
| 1 | MAC 在使用表 `mp` 中 | 返回已有 IP，状态不变 |
| 2 | MAC 在回收表 `jc` 中 | 移回使用表，返回自己的旧 IP |
| 3 | 存在从未使用的 IP | 按地址池顺序分配最小的一个 |
| 4 | 存在已释放的 IP | 分配最小回收地址，删除旧 MAC 的回收记录 |
| 5 | 全部 IP 都在使用 | 返回空字符串，状态不变 |

`Release` 只对使用表中的 MAC 成功：先复制记录到回收表，再从使用表删除。重复释放返回 false。

## 两张表分别表达什么

`mp` 表示当前有效的占用关系。`jc` 表示已释放、但还保留原 MAC 归属的空闲地址。一个地址在两张表里都找不到时，表示它从未使用过。

原 MAC 取回地址时，要把记录从 `jc` 移回 `mp`。其他 MAC 复用该地址时，要先删除 `jc` 中原 MAC 的记录。否则原 MAC 再次申请时可能返回一个已经被别人占用的 IP。

例如 A 释放 `.1` 后，如果 E 复用了 `.1`，A 就失去了直接取回 `.1` 的资格；A 以后仍可以申请其他可用地址。回收表不是永久历史记录。

地址池按最后一段数字升序生成，所以选择最小地址时扫描地址池即可。不能把字符串的字典序当作数值顺序：例如 `.10` 在字典序中可能排在 `.2` 前面。

## 原草稿中的修正

- 首次请求时使用表为空：现在仍会进入地址选择流程，并且所有分支都有返回值。
- 第一个 MAC 不匹配：现在继续遍历，完整查找结束后再处理不存在的情况。
- `baba` 未定义：补上明确的地址池和选择规则。
- 取回地址仅返回字符串：现在同时更新两张表，恢复占用状态。
- 删除后访问迭代器：现在先 `jc.push_back(*it)`，再 `mp.erase(it)` 并立即返回。
- 添加 `pair` 对应的 `<utility>`，移除未使用的 `<unordered_map>`，使用直接循环实现。

两个表中的 IP 始终互不重复，且互不重叠；同一个 MAC 至多出现在其中一张表。每次修改后保持这些条件，后续操作才不会发生地址冲突。

## 验证与运行

内置测试包含两个完整样例，以及重复请求、非首元素查找、重复释放、地址耗尽、失败请求不改变状态、旧地址被抢占后再次申请、按最小地址复用、个人旧地址优先和对象间状态独立等情况。

N 个地址的扫描版中，Request 最坏 O(N²)，Release 最坏 O(N)，总空间 O(N)。当前主版本保留原来的直观数据结构，适合练习分支顺序、状态变化和迭代器使用。
