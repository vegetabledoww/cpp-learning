# 多窗口事件分发系统

[solution.cpp](./solution.cpp) 包含完整中文题面、两个操作序列样例、题解和本地测试。原题平台与完整约束未知，题面根据提供的代码和示例恢复；补充约定有明确标注。

本题归入 `05_design_problems`：同一个 `MultiWindowSys` 对象需要持续维护窗口的位置和层级，各次接口调用会改变后续结果。矩形判断和 vector 扫描是实现这些接口的工具。

## 本学习版的规则

| 接口 | 成功条件与返回 | 对层级的影响 |
| --- | --- | --- |
| `CreateWindow` | ID 不存在则创建并返回 true；允许完全离屏创建 | 新窗口置顶 |
| `DestroyWindow` | ID 存在则删除并返回 true，否则 false | 其余窗口相对次序不变 |
| `MoveWindow` | ID 存在且移动后与屏幕有正面积交集，则返回 true | 移动的窗口置顶，同位置移动也置顶 |
| `DispatchClickEvent` | 屏幕内有窗口覆盖该点则返回最高层 ID，否则 -1 | 命中的窗口置顶 |

屏幕坐标为 `[0,1000) × [0,1000)`，窗口范围为 `[row,row+height) × [col,col+width)`。`width` 对应列方向，`height` 对应行方向。ID 为非负 int，尺寸为正 int；非法尺寸不在本练习输入范围。

“创建可完全离屏、移动后必须部分可见”来自提供的 main 注释，两者有意采用不同规则。本学习版另外约定屏幕外点击直接返回 -1；如果原题保证所有点击都在屏幕内，这一分支不会触发。窗口不裁剪尺寸，只限制哪些坐标能产生点击。

## 保留的思路

仍使用 `vector<window> w` 保存窗口，逐个扫描查 ID 或查命中，不增加额外索引表。`layer` 越大，窗口越靠上；任何成功置顶操作都使用 `++maxLayer`。删除窗口后层级可以有空缺，不需要重新编号。

移动仍先构造 `tmp`，确认其可见后再赋回原窗口。点击仍先扫描找 `topwindow`，扫描结束后再修改层级。

## 修正了哪些问题

1. **点击置顶的变量遮蔽。** 原稿在 `DispatchClickEvent` 中重新声明了局部 `maxLayer`，遮住对象成员。局部值只表示“这次命中的最高层”，不能代表系统内所有窗口的最高层。
2. **移动不存在 ID 时缺返回值。** 在遍历结束后补 `return false`，消除非 void 函数走到末尾的未定义行为。
3. **边界计算的整数溢出。** 坐标和尺寸分别是 int，但相加可能超过 int；在加法之前提升到 long long。层级计数也使用 long long。
4. **只读参数。** `contain` 改为接收 `const window&` 和按值传递的行列坐标；判断过程不修改它们。

最关键的反例是：窗口1层级为1，窗口2为2，窗口3为3。先点击只有窗口1覆盖的点，原实现可能只把它改成2，仍低于窗口3。正确置顶后必须是4，因此再点击三个窗口重叠处应命中1。源码的示例二专门检查这个问题。

## 验证与复杂度

测试涵盖提供的原始调用、点击低层窗口后全局置顶、多次点击后新建、移动置顶、重复创建、失败移动状态不变、删除后露出下层、ID重用、非正方形行列判断、半开边界、部分离屏、屏幕外点击、int边界相加和多实例隔离。每项打印 expected/actual，失败时程序返回非零退出码。

整理时使用 MinGW GCC 8.1，以 `-std=c++17 -Wall -Wextra -pedantic -Werror` 编译成功；运行全部内置检查，结果为 `failed=0`。此结果针对上面明确的学习版规则，未声称通过未知平台的在线评测。

当前有 W 个窗口时，各接口均为 O(W) 时间，系统存储空间 O(W)。采用扫描版本是为了清楚展示状态更新和边界规则，适合作为入门到中等难度的设计模拟题。
